6. React

Ở mức Middle, người phỏng vấn không hỏi "useState dùng thế nào" nữa. Họ hỏi vì sao component re-render, khi nào cần useMemo, và quản lý state ở đâu.

6.1. Cơ chế render Bắt buộc

  • Render phase: React gọi hàm component để tạo cây element mới, rồi so sánh với cây cũ (reconciliation). Commit phase: áp phần thay đổi vào DOM thật, sau đó chạy effect.
  • Component re-render khi: (1) state của nó thay đổi, (2) component cha re-render (dù props không đổi), (3) giá trị của Context mà nó dùng thay đổi. Re-render không có nghĩa là DOM thay đổi.
  • key giúp React biết phần tử nào là phần tử nào trong danh sách. Dùng id ổn định; dùng index làm key sẽ lỗi khi chèn, xóa hoặc sắp xếp lại (input giữ sai giá trị). Đổi key của một component thì component đó bị tạo mới hoàn toàn (đây cũng là một mẹo để reset state).
  • State là bất biến (immutable): luôn tạo object/array mới, không sửa trực tiếp. React so sánh bằng Object.is.
  • Batching: từ React 18, nhiều lệnh setState trong cùng một sự kiện (kể cả trong promise hay timeout) được gộp thành một lần render.
```tsx // SAI: sửa trực tiếp state nên React không thấy thay đổi todos.push(newTodo); setTodos(todos); // ĐÚNG setTodos((prev) => [...prev, newTodo]); setUser((prev) => ({ ...prev, address: { ...prev.address, city: 'Hà Nội' } })); // Functional update khi giá trị mới phụ thuộc giá trị cũ setCount(count + 1); setCount(count + 1); // chỉ tăng 1 (cùng một giá trị count cũ) setCount((c) => c + 1); setCount((c) => c + 1); // tăng 2 ```

Bạn có thể không cần useEffect (theo react.dev): dữ liệu tính được từ props/state thì tính trực tiếp khi render; logic phản hồi hành động của người dùng thì đặt trong event handler; fetch dữ liệu thì dùng TanStack Query hoặc framework.

```tsx // Fetch có cleanup để tránh race condition: gõ nhanh "a" → "ab", response của "a" về sau không được ghi đè useEffect(() => { const ctrl = new AbortController(); fetch(`/api/search?q=${q}`, { signal: ctrl.signal }) .then((r) => r.json()) .then(setResults) .catch((e) => { if (e.name !== 'AbortError') setError(e); }); return () => ctrl.abort(); // chạy trước lần effect tiếp theo và khi unmount }, [q]); // Custom hook: tái sử dụng logic có state function useDebounce(value: T, ms = 400) { const [v, setV] = useState(value); useEffect(() => { const t = setTimeout(() => setV(value), ms); return () => clearTimeout(t); }, [value, ms]); return v; } ```
StrictMode chạy effect 2 lần ở môi trường dev
Ở dev, React cố ý mount → unmount → mount lại để lộ ra những effect quên cleanup. Ở production thì effect chỉ chạy 1 lần. Đừng "sửa" bằng cách tắt StrictMode; hãy viết cleanup cho đúng.

```tsx type State = { items: CartItem[]; coupon?: string }; type Action = | { type: 'add'; item: CartItem } | { type: 'remove'; id: string } | { type: 'applyCoupon'; code: string }; function cartReducer(state: State, action: Action): State { switch (action.type) { case 'add': return { ...state, items: [...state.items, action.item] }; case 'remove': return { ...state, items: state.items.filter((i) => i.id !== action.id) }; case 'applyCoupon': return { ...state, coupon: action.code }; } } const [cart, dispatch] = useReducer(cartReducer, { items: [] }); dispatch({ type: 'add', item }); // dispatch có tham chiếu ổn định, truyền xuống con thoải mái ```

    7. Nền tảng frontend và trình duyệt

    7.1. HTML và CSS Bắt buộc

    • HTML semantic: header, nav, main, article, button (không dùng div onClick), label gắn với input. Tốt cho SEO và cho người dùng trình đọc màn hình.
    • Box model, box-sizing: border-box; position (relative, absolute, fixed, sticky), z-index và stacking context.
    • Flexbox cho bố cục một chiều (thanh menu, căn giữa); Grid cho bố cục hai chiều (lưới sản phẩm, layout trang).
    • Responsive: thiết kế mobile-first, media query, đơn vị rem/%/vw, clamp(); ảnh responsive dùng srcset.
    • Tailwind CSS rất phổ biến hiện nay. Ngoài ra nên biết CSS Modules và thư viện component (shadcn/ui, MUI, Ant Design).
    • Độ ưu tiên selector (specificity): inline > id > class/attribute/pseudo-class > element.

    7.2. Trình duyệt hoạt động thế nào Bắt buộc

    1. Phân giải DNS → kết nối TCP + TLS → gửi request HTTP → nhận HTML.
    2. Phân tích HTML thành DOM, CSS thành CSSOM, ghép lại thành render tree → layout (tính vị trí) → paint (vẽ) → composite (ghép các lớp).
    3. Thẻ <script> thường chặn việc phân tích HTML. defer tải song song và chạy sau khi phân tích xong, giữ đúng thứ tự. async chạy ngay khi tải xong, không giữ thứ tự.
    4. Thay đổi kích thước hay vị trí gây reflow (tốn kém). Chỉ đổi màu thì gây repaint. Hiệu ứng chuyển động nên dùng transform/opacity để chỉ phải composite.

    7.3. CORS, cookie, lưu trữ Bắt buộc

    • Same-origin policy: origin gồm giao thức + domain + port. Trình duyệt chặn JS đọc response từ origin khác, trừ khi server cho phép qua header Access-Control-Allow-Origin.
    • Preflight: với request "không đơn giản" (PUT, DELETE, PATCH, header tùy chỉnh như Authorization, Content-Type: application/json), trình duyệt gửi OPTIONS trước để hỏi.
    • Gửi cookie khác origin cần credentials: 'include' ở client và Access-Control-Allow-Credentials: true ở server. Khi đó Allow-Origin không được là *.
    • CORS là cơ chế của trình duyệt: Postman hay curl không bị chặn. Vì vậy CORS không thay thế được xác thực.
    • Thuộc tính cookie: HttpOnly (JS không đọc được, chống XSS lấy cookie), Secure (chỉ gửi qua HTTPS), SameSite=Lax (mặc định trên Chrome, chống phần lớn CSRF) / Strict / None (phải kèm Secure).

A: Là request `OPTIONS` mà trình duyệt tự gửi trước một request "không đơn giản" (method khác GET/POST/HEAD, có header tùy chỉnh, hoặc Content-Type là application/json) để hỏi server có cho phép không. Server trả về các header Allow-Methods/Allow-Headers; có thể cache kết quả bằng `Access-Control-Max-Age`. Q: SameSite của cookie có tác dụng gì? A: Nó quy định cookie có được gửi kèm request từ trang khác không. `Strict`: không bao giờ. `Lax` (mặc định): chỉ gửi khi điều hướng cấp cao nhất bằng GET (bấm link). `None`: luôn gửi, bắt buộc kèm `Secure`. Lax/Strict chặn được phần lớn tấn công CSRF. Q: defer và async khác nhau thế nào? A: Cả hai đều tải script song song với việc phân tích HTML. `defer` chạy sau khi phân tích xong và giữ đúng thứ tự các script, phù hợp cho script của app. `async` chạy ngay khi tải xong, không giữ thứ tự, phù hợp cho script độc lập như analytics. Q: Kể 3 chỉ số Core Web Vitals và một cách cải thiện mỗi chỉ số. A: LCP ≤ 2,5 giây: tối ưu và preload ảnh hero, dùng SSR hoặc CDN. INP ≤ 200 ms: chia nhỏ task dài, giảm lượng JS và re-render. CLS ≤ 0,1: khai báo kích thước cho ảnh và iframe, chừa sẵn chỗ cho nội dung tải sau. Q: Flexbox và Grid khác nhau thế nào? A: Flexbox sắp xếp theo một chiều (hàng hoặc cột), kích thước phụ thuộc nội dung, phù hợp cho thanh công cụ hay căn giữa. Grid sắp theo hai chiều (hàng và cột cùng lúc), phù hợp cho layout trang hay lưới thẻ.
