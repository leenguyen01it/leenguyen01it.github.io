11. Ôn lại PHP và Laravel

3 năm PHP là tài sản của bạn: nhiều công ty tuyển fullstack cần người vừa bảo trì hệ thống Laravel cũ vừa xây phần mới bằng Node/React, hoặc cần người chuyển dần hệ thống từ PHP sang Node. Phần này giúp bạn trả lời tự tin khi bị hỏi về PHP, và so sánh được hai nền tảng.

11.2. OOP, SOLID, chuẩn PSR Bắt buộc

  • OOP: interface và abstract class, trait (gom code dùng chung, giải quyết giới hạn đơn kế thừa), static và self (late static binding), magic method (__get, __call, __invoke).
  • SOLID: mỗi class một trách nhiệm (S); mở để mở rộng, đóng để sửa đổi (O); class con thay được cho class cha (L); interface nhỏ, chuyên biệt (I); phụ thuộc vào abstraction, không vào cài đặt cụ thể (D). Câu hỏi này gặp cả ở phỏng vấn PHP lẫn Node.
  • Composer + PSR-4 (autoload theo namespace), PSR-12/PER (coding style), PSR-7/15 (HTTP message, middleware), PSR-11 (container).
  • Công cụ chất lượng: PHPStan/Larastan (phân tích tĩnh), PHP CS Fixer/Pint, PHPUnit/Pest.

11.4. Laravel cốt lõi Bắt buộc

  • Vòng đời request: public/index.php → khởi tạo Application → HTTP Kernel → Service Provider (register rồi boot) → Middleware → Router → Controller → Response → terminable middleware.
  • Service Container và DI: bind, singleton, auto-resolve qua type hint. Facade là proxy tĩnh tới một service trong container.
  • Eloquent: quan hệ (hasMany, belongsTo, belongsToMany, polymorphic), eager loading with() để tránh N+1, chunk()/lazy() cho tập dữ liệu lớn, scope, accessor/mutator, $fillable để chống mass assignment, Model::preventLazyLoading() để phát hiện N+1 ở môi trường dev.
  • Validate: FormRequest. Phân quyền: Gate và Policy. Xác thực API: Sanctum (token/SPA), Passport (OAuth2).
  • Queue và Job (Redis/SQS, Horizon), Event/Listener, Scheduler, Cache, Notification.
  • Bảo mật có sẵn: PDO prepared statement (query builder), {{ }} trong Blade tự escape, @csrf, Hash::make (bcrypt/argon2), mã hóa cookie.
```php // N+1: 1 query + N query lấy author $posts = Post::latest()->take(20)->get(); foreach ($posts as $p) echo $p->author->name; // Eager loading: tổng cộng 2 query $posts = Post::with('author:id,name')->latest()->take(20)->get(); // Trừ tồn kho an toàn trong transaction DB::transaction(function () use ($productId, $qty) { $affected = Product::where('id', $productId)->where('stock', '>=', $qty)->decrement('stock', $qty); if ($affected === 0) throw new OutOfStockException(); }); ```

11.5. Chuyển hệ thống từ PHP sang Node Điểm cộng

Nếu được hỏi "nếu cần chuyển hệ thống Laravel sang Node thì bạn làm thế nào", hãy trả lời theo hướng Strangler Fig: đặt một proxy hoặc API gateway phía trước, chuyển từng module (thường bắt đầu từ phần cần realtime hoặc phần chịu tải cao) sang service Node mới; hai bên có thể dùng chung DB trong giai đoạn chuyển tiếp hoặc đồng bộ qua sự kiện; xác thực dùng chung (JWT/session trong Redis); chuyển xong module nào thì tắt module đó bên PHP. Không viết lại toàn bộ một lần.

```qa Q: PHP-FPM xử lý request khác Node.js thế nào? A: PHP-FPM có pool worker; mỗi request chiếm một worker từ đầu đến cuối, kể cả lúc chờ I/O, và trạng thái bị dọn sạch sau mỗi request (share-nothing). Node chạy một process với event loop, trong lúc chờ I/O thì xử lý request khác, và process sống lâu nên trạng thái global còn lại qua các request. A: Trait là cách dùng lại code (method, thuộc tính) giữa các class mà không qua kế thừa; dùng bằng `use TraitName`. Interface chỉ khai báo hợp đồng, không có cài đặt (từ PHP 8 vẫn vậy). Một class implement được nhiều interface và dùng được nhiều trait. Q: Giải thích SOLID kèm ví dụ cho chữ D. A: S: mỗi class một trách nhiệm. O: mở rộng mà không sửa code cũ. L: class con thay được class cha. I: interface nhỏ, chuyên biệt. D: phụ thuộc vào abstraction. Ví dụ cho D: `OrderService` nhận `PaymentGateway` (interface) qua constructor thay vì tự `new StripeClient()`. Nhờ vậy đổi sang VNPay hay mock khi test chỉ cần bind một cài đặt khác trong container. Tốt nhất là chỉ dùng `$request->validated()`. Q: Nếu phải chọn giữa Laravel và Node cho một dự án mới, bạn cân nhắc gì? A: Laravel: làm CRUD, trang quản trị, thương mại điện tử truyền thống rất nhanh vì hệ sinh thái có sẵn đủ thứ (auth, queue, mail). Node: cần realtime, nhiều kết nối đồng thời, muốn dùng chung TypeScript giữa frontend và backend, làm microservice, hoặc team đã mạnh về JS. Ngoài ra còn phụ thuộc kỹ năng của team, khả năng tuyển người và hệ thống hiện có. ``` ```quiz Q: Tính năng nào xuất hiện từ PHP 8.1? - Toán tử nullsafe `?->` + `enum` - Named arguments - `match` E: Nullsafe, named arguments và match có từ PHP 8.0. 12.1. Tự viết Promise.all

```js function promiseAll(items) { return new Promise((resolve, reject) => { const results = new Array(items.length); let done = 0; if (items.length === 0) return resolve(results); items.forEach((item, i) => { Promise.resolve(item).then((v) => { // chấp nhận cả giá trị không phải promise results[i] = v; // giữ đúng thứ tự đầu vào if (++done === items.length) resolve(results); }, reject); // lỗi đầu tiên → reject ngay }); }); } ```

12.2. Giới hạn số việc chạy đồng thời

Đề bài: có 1.000 URL cần tải, nhưng chỉ được chạy tối đa 5 request cùng lúc.

```js async function mapLimit(items, limit, fn) { const results = new Array(items.length); let next = 0; async function worker() { while (next < items.length) { const i = next++; // an toàn vì JS đơn luồng results[i] = await fn(items[i], i); } } await Promise.all(Array.from({ length: Math.min(limit, items.length) }, worker)); return results; } // await mapLimit(urls, 5, (u) => fetch(u).then((r) => r.json())); ```

12.3. LRU cache

Đề bài: cache có dung lượng cố định; khi đầy thì loại phần tử lâu nhất chưa được dùng. Yêu cầu get/put chạy trong O(1).

```js class LRUCache { constructor(capacity) { this.capacity = capacity; this.map = new Map(); } // Map giữ thứ tự chèn get(key) { if (!this.map.has(key)) return -1; const v = this.map.get(key); this.map.delete(key); this.map.set(key, v); // đưa lên cuối = vừa được dùng return v; } put(key, value) { this.map.delete(key); this.map.set(key, value); if (this.map.size > this.capacity) this.map.delete(this.map.keys().next().value); // xóa phần tử đầu = cũ nhất } } ```

[]).filter((f) => f !== fn)); } once(name, fn) { const off = this.on(name, (...a) => { off(); fn(...a); }); } emit(name, ...args) { (this.#events.get(name) ?? 12.6. Phỏng vấn hành vi: trả lời theo STAR

STAR = Situation (bối cảnh) → Task (nhiệm vụ của bạn) → Action (bạn đã làm gì, nói "tôi" chứ không phải "chúng tôi") → Result (kết quả, có số liệu nếu được). Mỗi câu trả lời khoảng 1–2 phút.
