1. JavaScript nâng cao và TypeScript

Đây là phần nền của cả backend lẫn frontend. Rất nhiều buổi phỏng vấn Middle mở đầu bằng 10–15 phút hỏi JavaScript core.

1.1. Scope, closure, hoisting Bắt buộc

  • var / let / const: var có function scope và được hoisting với giá trị undefined. let/const có block scope và nằm trong Temporal Dead Zone cho đến dòng khai báo.
  • Closure: hàm "nhớ" các biến của scope nơi nó được tạo ra, kể cả khi scope đó đã chạy xong. Ứng dụng: đóng gói dữ liệu, factory function, memoize, debounce.
```js // Câu hỏi kinh điển: in ra gì? for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0); // 3 3 3 for (let j = 0; j < 3; j++) setTimeout(() => console.log(j), 0); // 0 1 2 // let tạo một biến j mới cho mỗi vòng lặp; var dùng chung một biến i. // Closure: bộ đếm có dữ liệu "private" function createCounter() { let count = 0; return { inc: () => ++count, get: () => count }; } const c = createCounter(); c.inc(); c.inc(); console.log(c.get()); // 2 ```

1.2. this, prototype, class Bắt buộc

  • this được xác định lúc gọi hàm, không phải lúc khai báo: obj.fn() thì this = obj. Gọi hàm rời (fn()) thì this là undefined trong strict mode.
  • Arrow function không có this riêng mà lấy this của scope bao ngoài. Vì vậy không nên dùng arrow function làm method của object.
  • call/apply gọi hàm với this chỉ định; bind trả về một hàm mới đã gắn cố định this.
  • class chỉ là cú pháp đẹp hơn cho prototype. Mỗi object có [[Prototype]]; khi tìm thuộc tính, JS đi ngược lên chuỗi prototype.

1.3. Kiểu dữ liệu, so sánh, sao chép Bắt buộc

  • 7 kiểu nguyên thủy (string, number, bigint, boolean, undefined, null, symbol) được truyền theo giá trị. Object, array, function được truyền theo tham chiếu.
  • Luôn dùng ===. Cần biết == có ép kiểu (0 == '' cho kết quả true).
  • Shallow copy: {...obj}, [...arr], Object.assign. Deep copy: structuredClone(obj). Cách JSON.parse(JSON.stringify()) làm mất Date, Map, undefined, function.
  • ?? khác ||: ?? chỉ thay khi giá trị là null/undefined, còn || thay cả với 0, '', false.
  • Cấu trúc dữ liệu: Map (key là kiểu bất kỳ, giữ thứ tự), Set (loại trùng), WeakMap (key là object, không chặn garbage collection).

Đây là mảng quan trọng nhất với người chuyển từ PHP sang, vì PHP chạy tuần tự còn Node thì không.

1.5. Hàm bậc cao và các mẫu hay hỏi Bắt buộc

Bạn cần dùng thành thạo map, filter, reduce, some, every, find, flatMap, destructuring, rest/spread và optional chaining ?.. Hai bài code hay bị yêu cầu viết tay:

```js // Debounce: chỉ chạy sau khi người dùng ngừng gõ `ms` mili giây (ô tìm kiếm) function debounce(fn, ms) { let timer; return (...args) => { clearTimeout(timer); timer = setTimeout(() => fn(...args), ms); }; } // Throttle: chạy tối đa 1 lần mỗi `ms` mili giây (sự kiện scroll, resize) function throttle(fn, ms) { let last = 0; return (...args) => { const now = Date.now(); if (now - last >= ms) { last = now; fn(...args); } }; } ```

1.6. TypeScript Bắt buộc

Ở mức Middle, hầu hết JD (mô tả công việc) đều ghi TypeScript là yêu cầu bắt buộc. Bạn cần biết:

  • Kiểu cơ bản, type và interface: interface có thể mở rộng/gộp khai báo, phù hợp mô tả object; type dùng được cho union, tuple và mapped type.
  • Union và narrowing: thu hẹp kiểu bằng typeof, in, instanceof, hoặc type guard tự viết.
  • Generics: viết hàm/kiểu dùng lại được mà vẫn giữ đúng kiểu dữ liệu.
  • Utility types: Partial, Required, Pick, Omit, Record, ReturnType, Awaited.
  • unknown và any: unknown buộc phải kiểm tra kiểu trước khi dùng nên an toàn hơn. Nên tránh any.
  • never dùng để kiểm tra đã xử lý hết mọi trường hợp; satisfies kiểm tra kiểu mà không làm mất kiểu cụ thể.
  • Bật "strict": true trong tsconfig.json.
```ts // Discriminated union + kiểm tra đã xử lý hết trường hợp type ApiResult = | { status: 'success'; data: T } | { status: 'error'; message: string }; function render(r: ApiResult) { switch (r.status) { case 'success': return r.data; // TS biết r có data case 'error': return r.message; // TS biết r có message default: { const _never: never = r; return _never; } // thêm status mới mà quên xử lý → báo lỗi } } // Generic có ràng buộc function pluck(items: T[], key: K): T[K][] { return items.map((i) => i[key]); } // Utility types cho DTO interface User { id: number; email: string; password: string; createdAt: Date } type PublicUser = Omit; type UpdateUserDto = Partial>; ``` ```qa Q: Closure là gì? Cho một ví dụ dùng closure trong dự án thật. A: Closure là một hàm cùng với các biến của scope nơi hàm đó được tạo ra. Hàm vẫn dùng được các biến này dù scope bên ngoài đã chạy xong. Ví dụ trong dự án: middleware factory `requireRole('admin')` trả về một middleware nhớ được role; hàm debounce nhớ `timer`; module giữ biến private. Q: Khác nhau giữa `var`, `let`, `const`? A: `var` có function scope, được hoisting với giá trị `undefined` và khai báo lại được. `let` và `const` có block scope và nằm trong TDZ trước dòng khai báo. `const` không gán lại được, nhưng object khai báo bằng `const` vẫn sửa được nội dung bên trong. Q: Arrow function khác function thường ở điểm nào? A: Arrow function không có `this`, `arguments` và `prototype` riêng, nên không dùng làm constructor với `new` được. `this` của nó lấy từ scope bao ngoài, vì thế rất tiện cho callback trong method, nhưng không nên dùng làm method của object. Q: `Promise.all` và `Promise.allSettled` khác nhau thế nào? Khi nào dùng cái nào? A: `all` reject ngay khi có một promise lỗi, nên hợp với các việc mà thiếu một cái là cả kết quả vô nghĩa. `allSettled` chờ tất cả chạy xong và trả về trạng thái của từng cái, nên hợp với các việc độc lập như gửi thông báo hàng loạt, cái nào lỗi thì ghi log cái đó. Q: Vì sao `await` bên trong `forEach` không hoạt động như mong đợi? A: `forEach` không quan tâm promise mà callback trả về, nên nó gọi hết các callback rồi kết thúc ngay. Trong một dự án nên thống nhất một quy ước. Q: `unknown` khác `any` thế nào? 2. Node.js core

Đây là phần phân biệt rõ nhất giữa người "biết dùng Express" và một Middle thực thụ.

2.1. Kiến trúc và event loop Bắt buộc

Node.js = engine V8 (chạy JS) + libuv (event loop, I/O bất đồng bộ). Code JS của bạn chạy trên một luồng. Network I/O dùng cơ chế bất đồng bộ của hệ điều hành (epoll, kqueue). Một số việc như fs, dns.lookup, crypto.pbkdf2, zlib chạy trên thread pool của libuv (mặc định 4 luồng, đổi bằng UV_THREADPOOL_SIZE).

```js // CommonJS (file .js không có "type": "module") console.log('1'); setTimeout(() => console.log('timeout'), 0); setImmediate(() => console.log('immediate')); Promise.resolve().then(() => console.log('promise')); process.nextTick(() => console.log('nextTick')); console.log('2'); // Kết quả: 1, 2, nextTick, promise, rồi timeout/immediate (thứ tự 2 cái cuối KHÔNG cố định) // Nếu đặt trong callback của fs.readFile thì immediate LUÔN chạy trước timeout. // Trong ES module, code top-level chạy như một microtask nên 'promise' in trước 'nextTick'. ```
Chặn event loop = cả server đứng hình
Một vòng lặp tính toán nặng, JSON.parse file 200 MB, regex tệ (ReDoS) hay fs.readFileSync trong request handler đều làm mọi request khác phải chờ. Cách xử lý: chia nhỏ công việc, dùng worker_threads cho việc nặng CPU, đẩy việc vào hàng đợi (BullMQ), dùng stream cho file lớn.

2.3. Stream và Buffer Nên biết

  • 4 loại stream: Readable (đọc file, request), Writable (ghi file, response), Duplex (socket), Transform (nén, mã hóa).
  • Backpressure: khi bên ghi chậm hơn bên đọc, stream tạm dừng việc đọc để RAM không bị đầy. Hàm pipeline xử lý việc này và cả lỗi cho bạn.
  • Buffer là dữ liệu nhị phân. Dùng khi xử lý file, ảnh, mã hóa.
```js import { createReadStream, createWriteStream } from 'node:fs'; import { createGzip } from 'node:zlib'; import { pipeline } from 'node:stream/promises'; // Nén file 5 GB mà chỉ tốn vài MB RAM await pipeline(createReadStream('big.log'), createGzip(), createWriteStream('big.log.gz')); // Express: trả file CSV lớn theo dạng stream thay vì đọc hết vào RAM app.get('/export', (req, res) => { res.setHeader('Content-Type', 'text/csv'); createReadStream('report.csv').pipe(res); }); ```

2.4. Xử lý lỗi Bắt buộc

  • Phân biệt lỗi vận hành (DB mất kết nối, input sai, gọi API timeout): bắt lỗi và trả về response phù hợp. Còn lỗi lập trình (bug, undefined is not a function): ghi log và để process khởi động lại.
  • Tự tạo class lỗi có statusCode, rồi xử lý tập trung ở một middleware.
  • Từ Node 15, một unhandledRejection sẽ làm process tắt. Hãy ghi log trong process.on('unhandledRejection') và uncaughtException, rồi thoát để PM2/Docker khởi động lại.
```ts export class AppError extends Error { constructor(public statusCode: number, message: string, public code = 'APP_ERROR') { super(message); } } export class NotFoundError extends AppError { constructor(resource: string) { super(404, `${resource} không tồn tại`, 'NOT_FOUND'); } } ```

2.5. Tận dụng nhiều nhân CPU Nên biết

  • Cluster / PM2 (pm2 start app.js -i max): chạy nhiều process, mỗi process một nhân CPU, dùng chung một port. Các process không chia sẻ bộ nhớ, nên session và cache phải để trong Redis.
  • worker_threads: luồng riêng cho tác vụ nặng CPU (xử lý ảnh, tạo PDF, mã hóa), không làm chặn event loop chính.
  • child_process: chạy chương trình bên ngoài (ffmpeg, script Python).
  • Trong Kubernetes thường chạy mỗi container một process và scale bằng số lượng pod.

2.6. EventEmitter, cấu hình, hiệu năng Nên biết

  • EventEmitter: nền tảng của stream, server, socket. Nhớ gỡ listener (off) để tránh rò rỉ bộ nhớ.
  • Cấu hình: đọc từ biến môi trường và validate ngay khi khởi động. Thiếu biến thì báo lỗi ngay, không để đến lúc chạy mới lỗi.

A: Chỉ phần chạy code JS là đơn luồng. I/O như mạng, file hay DB được giao cho hệ điều hành hoặc thread pool của libuv. Trong lúc chờ I/O, event loop tiếp tục nhận request khác; khi I/O xong thì callback được đưa vào hàng đợi để chạy. Mô hình này rất hợp với ứng dụng nhiều I/O, nhưng không hợp với việc nặng CPU. Q: Kể các pha của event loop. `process.nextTick` và Promise chạy lúc nào? A: Các pha là timers → pending callbacks → (idle/prepare) → poll → check → close callbacks. Sau mỗi callback, Node chạy hết hàng đợi `nextTick`, rồi đến hết hàng đợi microtask của Promise, sau đó mới sang callback hoặc pha tiếp theo. Q: `setImmediate` khác `setTimeout(fn, 0)` thế nào? A: `setImmediate` chạy ở pha check, ngay sau pha poll. `setTimeout 0` chạy ở pha timers. Trong code chính, thứ tự hai cái không cố định; trong callback I/O thì `setImmediate` luôn chạy trước. Q: Làm sao biết event loop đang bị chặn và xử lý thế nào? A: Dấu hiệu là latency tăng đều ở mọi endpoint và CPU 100% trên một nhân. Đo bằng `perf_hooks.monitorEventLoopDelay` hoặc clinic.js, tìm hàm nóng bằng CPU profile. Cách xử lý: dùng hàm async thay hàm sync, chuyển việc nặng sang worker_threads hoặc hàng đợi, dùng stream cho dữ liệu lớn, sửa regex dễ bị ReDoS. Q: Backpressure là gì? A: Là khi bên nhận dữ liệu (Writable) xử lý chậm hơn bên gửi (Readable). `write()` trả về false thì bên gửi phải dừng lại cho đến khi có sự kiện `drain`. `pipe` và `pipeline` tự xử lý việc này, nhờ vậy RAM không bị đầy. Q: Cluster và worker_threads khác nhau thế nào? A: Cluster tạo nhiều process, mỗi cái có bộ nhớ và event loop riêng, dùng chung port, dùng để scale khả năng xử lý request HTTP. worker_threads là các luồng trong cùng một process, có thể chia sẻ bộ nhớ (SharedArrayBuffer), dùng cho tác vụ nặng CPU. Q: Khi gặp `uncaughtException` có nên để app chạy tiếp không? A: Không nên. Lúc đó trạng thái của app có thể đã hỏng. Đúng cách là ghi log, đóng kết nối một cách êm (graceful shutdown) rồi thoát process; PM2, Docker hoặc Kubernetes sẽ khởi động lại. Q: Những nguyên nhân phổ biến gây rò rỉ bộ nhớ trong Node? A: Cache bằng object/Map global mà không giới hạn hay đặt TTL; thêm event listener mà không gỡ; `setInterval` không clear; closure giữ tham chiếu tới object lớn; mảng log tăng mãi.
