13. Làm việc với AI coding agent (Claude Code, Codex…)

Đến năm 2026, phần lớn đội phần mềm đều dùng AI coding agent, và câu hỏi "Bạn dùng AI trong công việc thế nào?" đã trở thành câu phỏng vấn quen thuộc. Người phỏng vấn không cần biết bạn thuộc bao nhiêu tính năng. Họ muốn biết bạn có giao việc rõ ràng, có kiểm chứng kết quả và có chịu trách nhiệm với code AI viết ra không. Một Middle dùng agent tốt sẽ làm nhanh gấp nhiều lần; dùng kém thì đưa bug và lỗ hổng bảo mật lên production nhanh gấp nhiều lần.

Nguyên tắc gốc
Bạn chịu trách nhiệm cho mọi dòng code được merge, kể cả dòng do AI viết. Không merge code mà bạn không giải thích được.

13.1. Agent khác gì chatbot và autocomplete Bắt buộc

LoạiVí dụLàm được gì

ChatHỏi đáp trên claude.ai, ChatGPTGiải thích, viết đoạn code; bạn tự copy và tự chạy
Coding agentClaude Code, Codex (CLI/cloud), Cursor/Copilot ở chế độ agentTự đọc codebase, sửa nhiều file, chạy lệnh (test, lint, git), đọc kết quả rồi sửa tiếp cho đến khi xong

Agent hoạt động theo vòng lặp: đọc ngữ cảnh → lập kế hoạch → dùng công cụ (đọc/sửa file, chạy lệnh) → quan sát kết quả → lặp lại. Chất lượng đầu ra phụ thuộc chủ yếu vào ngữ cảnh bạn cung cấp và cách nó tự kiểm tra (test, type-check).

13.2. Quy trình làm việc hiệu quả Bắt buộc

  1. Khám phá: yêu cầu agent đọc và tóm tắt phần code liên quan trước khi sửa ("đọc module orders và giải thích luồng tạo đơn, chưa sửa gì").
  2. Lập kế hoạch: với việc lớn, bảo agent đề xuất kế hoạch (Claude Code có plan mode). Bạn duyệt, sửa kế hoạch rồi mới cho làm.
  3. Làm từng bước nhỏ: mỗi lần một thay đổi có thể kiểm chứng được. Đừng giao "làm cả tính năng thanh toán" trong một câu.
  4. Kiểm chứng tự động: cho agent chạy test, lint, type-check và tự sửa đến khi pass. Tốt nhất là viết (hoặc cho agent viết) test trước, kiểu TDD.
  5. Review diff như review code đồng nghiệp: đọc từng thay đổi, chạy thử, kiểm tra trường hợp biên và bảo mật.
  6. Commit nhỏ, thường xuyên: để dễ quay lại nếu agent đi sai hướng.

Một yêu cầu tốt gồm: mục tiêu, ngữ cảnh (file và module liên quan), ràng buộc (không đổi API công khai, theo đúng convention), tiêu chí hoàn thành (test nào phải pass) và cách kiểm chứng.

```text Thêm phân trang cursor cho GET /api/v1/products. Ngữ cảnh: route ở src/modules/products/products.controller.ts, dùng Prisma. Làm giống cách phân trang của orders (src/modules/orders/orders.service.ts). Ràng buộc: giữ nguyên dạng response { data, meta }; thêm meta.nextCursor; limit tối đa 100. Hoàn thành khi: - Có integration test cho: trang đầu, trang tiếp theo, limit vượt 100, cursor sai định dạng - npm run lint, npm run typecheck, npm test đều pass Trước khi sửa, hãy đưa ra kế hoạch ngắn để tôi duyệt. ```

13.3. Cung cấp ngữ cảnh cho agent Bắt buộc

  • File hướng dẫn dự án: CLAUDE.md (Claude Code) và AGENTS.md (Codex và nhiều agent khác) được nạp tự động. Nên ghi: lệnh build/test/lint, cấu trúc thư mục, convention, những điều không được làm. Viết ngắn gọn, cụ thể và cập nhật khi dự án thay đổi.
  • Chỉ rõ file liên quan và một ví dụ mẫu có sẵn trong code ("làm giống file X") thay vì mô tả dài.
  • Quản lý context: context window có giới hạn, và hội thoại càng dài thì agent càng dễ "quên" hoặc lẫn lộn. Mỗi việc mới nên bắt đầu một phiên mới (/clear); phiên dài thì tóm gọn (/compact); việc tìm kiếm rộng có thể giao cho subagent.
```text # CLAUDE.md / AGENTS.md (ví dụ ngắn) ## Lệnh - Cài đặt: pnpm i · Dev: pnpm dev · Test: pnpm test · Kiểm tra: pnpm lint && pnpm typecheck ## Quy ước - NestJS, mỗi tính năng một module trong src/modules/ - Validate bằng class-validator trong DTO; không dùng `any` - Mọi endpoint mới phải có integration test (Supertest) ## Không được - Sửa file migration đã có; muốn đổi schema thì tạo migration mới - Commit file .env hoặc in secret ra log ```

Các công cụ này cập nhật hằng tháng, nên tên lệnh và tính năng có thể thay đổi. Điều cần nắm là khái niệm: ngữ cảnh, kế hoạch, quyền hạn, kiểm chứng, tự động hóa.

  • Hook (Claude Code): chạy lệnh tự động theo sự kiện, ví dụ chạy Prettier sau mỗi lần sửa file, hoặc chặn việc sửa .env. Hook đảm bảo quy tắc luôn được thực thi; ghi trong CLAUDE.md thì agent chỉ "cố gắng nhớ".
  • MCP (Model Context Protocol): chuẩn mở để kết nối agent với công cụ và dữ liệu bên ngoài như GitHub, Postgres, Sentry, trình duyệt.
  • Subagent: agent con có context riêng, chuyên một việc (tìm code, review), giúp context của phiên chính không bị đầy.

Câu trả lời mẫu cho "Bạn dùng AI coding tool thế nào?": "Hằng ngày tôi dùng Claude Code và Codex. Dự án có file CLAUDE.md/AGENTS.md ghi lệnh và quy ước. Với tính năng mới, tôi cho agent đọc code và đề xuất kế hoạch, tôi duyệt kế hoạch, sau đó nó làm từng bước nhỏ và phải pass test, lint, type-check. Tôi review diff như review code của đồng nghiệp, đặc biệt các phần phân quyền và query DB. Ví dụ gần nhất: tôi dùng agent viết integration test cho module đơn hàng, độ phủ tăng từ 40% lên 75% trong hai ngày, và qua đó phát hiện một lỗi IDOR. Tôi không merge code mà tôi không giải thích được."
