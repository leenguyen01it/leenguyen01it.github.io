3.1. Class và object

Class là bản thiết kế; object là một thực thể cụ thể tạo từ bản thiết kế đó. Mỗi object có thuộc tính (dữ liệu) và phương thức (hành vi).

python
class TaiKhoan:
    lai_suat = 0.05                    # thuộc tính của class, dùng chung

    def __init__(self, chu_tk: str, so_du: float = 0):
        self.chu_tk = chu_tk           # thuộc tính của từng object
        self._so_du = so_du            # dấu _ = quy ước "nội bộ"

    def nap(self, so_tien: float) -> None:
        if so_tien <= 0:
            raise ValueError("Số tiền phải dương")
        self._so_du += so_tien

    @property
    def so_du(self) -> float:          # đọc như thuộc tính, không sửa trực tiếp được
        return self._so_du

    def __str__(self):
        return f"{self.chu_tk}: {self._so_du:,.0f} đ"

tk = TaiKhoan("An", 1_000_000)
tk.nap(500_000)
print(tk)             # An: 1,500,000 đ

3.6. Decorator

Decorator là hàm nhận một hàm và trả về hàm đã được bọc thêm hành vi. Các framework agent dùng decorator liên tục (ví dụ @tool, @app.get).

python
import time, functools

def do_thoi_gian(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        bat_dau = time.perf_counter()
        ket_qua = func(*args, **kwargs)
        print(f"{func.__name__} mất {time.perf_counter() - bat_dau:.3f}s")
        return ket_qua
    return wrapper

def thu_lai(so_lan=3):                  # decorator có tham số
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for lan in range(so_lan):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"Lần {lan + 1} lỗi: {e}")
            raise RuntimeError("Hết lượt thử")
        return wrapper
    return decorator

3.7. Iterator, generator và context manager

Generator tạo giá trị từng cái một bằng yield, không nạp hết vào bộ nhớ. Đây chính là cơ chế streaming khi LLM trả chữ từng phần.

python
def doc_file_lon(duong_dan):
    with open(duong_dan, encoding="utf-8") as f:
        for dong in f:
            yield dong.strip()

def chia_doan(van_ban: str, kich_thuoc: int = 500):
    for i in range(0, len(van_ban), kich_thuoc):
        yield van_ban[i:i + kich_thuoc]       # "chunking" trong RAG

tong = sum(x * x for x in range(1_000_000))   # generator expression

from contextlib import contextmanager
@contextmanager
def bam_gio(ten):
    t = time.perf_counter()
    yield
    print(f"{ten}: {time.perf_counter() - t:.2f}s")

with bam_gio("xử lý"):
    sum(range(10_000_000))

Tool calling (function calling)

Mô hình không tự chạy code. Nó chỉ trả về "tôi muốn gọi tool X với tham số Y"; code của bạn chạy tool rồi gửi kết quả lại.

  1. Bạn gửi câu hỏi + danh sách tool (tên, mô tả, schema tham số).

  2. Mô hình trả về khối tool_use với stop_reason = "tool_use".

  3. Code của bạn chạy hàm tương ứng.

  4. Bạn gửi lại khối tool_result.

  5. Mô hình dùng kết quả để trả lời (hoặc gọi tool tiếp). Lặp bước 2–5 chính là agent.

Chi phí, lỗi và thử lại

  • Chi phí = token vào × giá vào + token ra × giá ra (giá tra trên trang pricing). Ghi resp.usage cho mọi lệnh gọi.

  • Prompt caching: phần đầu prompt lặp lại (system prompt dài, tài liệu) có thể được cache để giảm mạnh chi phí và độ trễ.

  • Lỗi 429 (quá giới hạn) và 5xx: thử lại với thời gian chờ tăng dần (exponential backoff). SDK thường có sẵn max_retries.

  • Chọn model theo việc: model nhỏ, rẻ cho phân loại/trích xuất; model lớn cho suy luận phức tạp.

  • Chạy mô hình mở trên máy mình bằng Ollama để thử nghiệm miễn phí.

Bài tập và dự án

  1. Chatbot dòng lệnh có streaming, lệnh /reset, hiển thị tổng token và chi phí sau mỗi lượt.

  2. Phân loại 100 đánh giá sản phẩm, chạy song song bằng asyncio + Semaphore, so độ chính xác giữa 2 phiên bản prompt.

  3. Dự án: công cụ trích xuất CV → JSON (họ tên, kỹ năng, số năm kinh nghiệm), kiểm tra bằng Pydantic, tự thử lại khi JSON sai, xuất kết quả ra CSV.

5.3. RAG — cho LLM đọc dữ liệu riêng (3 tuần)

RAG (Retrieval-Augmented Generation) giải quyết việc LLM không biết tài liệu nội bộ của bạn: trước khi hỏi, hệ thống tìm các đoạn tài liệu liên quan rồi nhét vào prompt.

Hai luồng của một hệ RAG

Lập chỉ mục (chạy một lần hoặc khi tài liệu đổi):

  1. Nạp tài liệu (PDF, Word, web, database) và trích văn bản.

  2. Làm sạch và chia nhỏ thành đoạn (chunk).

  3. Biến mỗi đoạn thành vector bằng mô hình embedding.

  4. Lưu vector + văn bản + metadata (nguồn, trang, ngày) vào vector database.

Truy vấn (mỗi câu hỏi):

  1. Biến câu hỏi thành vector.

  2. Tìm k đoạn gần nhất (và có thể kết hợp tìm theo từ khóa).

  3. Xếp hạng lại, giữ các đoạn tốt nhất.

  4. Đưa các đoạn vào prompt, yêu cầu trả lời chỉ dựa trên chúng và trích nguồn.

Embedding và độ tương đồng

Embedding biến văn bản thành một dãy số (vector) sao cho các câu cùng ý nghĩa nằm gần nhau, kể cả khi khác từ ngữ. Độ gần thường đo bằng cosine similarity:

cos(a, b) = (a · b) / (‖a‖ · ‖b‖)
python
# pip install sentence-transformers numpy
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("...")   # chọn model embedding đa ngôn ngữ, hỗ trợ tiếng Việt
cau = ["Cách đổi mật khẩu", "Tôi quên password", "Giá vàng hôm nay"]
vec = model.encode(cau, normalize_embeddings=True)
print(vec @ vec.T)    # câu 1 và 2 gần nhau hơn hẳn câu 3

Có thể dùng API embedding của nhà cung cấp hoặc model mở chạy local. Tham khảo bảng xếp hạng MTEB trên Hugging Face để chọn model, ưu tiên model đa ngôn ngữ.

Nâng cao chất lượng truy xuất

  • Hybrid search: kết hợp tìm vector với BM25 (từ khóa). BM25 bắt tốt mã sản phẩm, tên riêng, số hiệu văn bản mà vector hay bỏ lỡ.

  • Rerank: lấy 20–50 ứng viên rồi dùng mô hình rerank (cross-encoder) chấm lại, giữ 3–5 đoạn tốt nhất.

  • Viết lại câu hỏi: dùng LLM tách câu hỏi phức tạp thành nhiều truy vấn con.

  • Lọc theo metadata: phòng ban, ngày hiệu lực, quyền truy cập của người hỏi.

  • Agentic RAG: biến tìm kiếm thành một tool để agent tự quyết định tìm gì, tìm mấy lần (chặng 5.4).

  • Khi nào không cần RAG: tài liệu nhỏ vừa context window thì nhét thẳng vào prompt (kèm prompt caching) thường đơn giản và chính xác hơn.

Trợ lý hỏi đáp tài liệu: nạp một thư mục PDF (quy chế công ty, giáo trình, luật), trả lời có trích trang, nói "không tìm thấy" khi không có; có bộ 30 câu hỏi đánh giá; so sánh 2 cách chunk và có/không rerank; giao diện đơn giản bằng Streamlit hoặc Gradio.

5.4. Xây dựng AI Agent (5–6 tuần)

Agent là LLM được trao tool và được chạy trong vòng lặp: nó tự quyết định bước tiếp theo dựa trên kết quả của bước trước, cho đến khi xong việc. Đây là phần quan trọng nhất của lộ trình.

Workflow hay agent?

Các mẫu workflow nên biết:

  1. Prompt chaining: chuỗi bước nối tiếp, có kiểm tra giữa các bước.

  2. Routing: phân loại đầu vào rồi chuyển tới prompt/model phù hợp.

  3. Parallelization: chạy nhiều lệnh gọi song song rồi gộp, hoặc bỏ phiếu.

  4. Orchestrator–workers: một LLM chia việc, nhiều LLM con làm, rồi tổng hợp.

  5. Evaluator–optimizer: một LLM viết, một LLM chấm và góp ý, lặp đến khi đạt.

Tự viết vòng lặp agent (không framework)

Hãy gõ tay đoạn này. Hiểu nó thì mọi framework về sau chỉ còn là cú pháp.

python
import json
from anthropic import Anthropic

client = Anthropic()
MODEL = "..."

# 1. Định nghĩa tool: hàm Python + mô tả cho LLM
def tim_kiem_san_pham(tu_khoa: str, gia_toi_da: int | None = None) -> list[dict]:
    du_lieu = [{"ten": "Tai nghe A", "gia": 450_000}, {"ten": "Tai nghe B", "gia": 1_200_000}]
    return [p for p in du_lieu if tu_khoa.lower() in p["ten"].lower()
            and (gia_toi_da is None or p["gia"] <= gia_toi_da)]

def tinh_toan(bieu_thuc: str) -> str:
    return str(eval(bieu_thuc, {"__builtins__": {}}))   # chỉ để học, không dùng thật

TOOLS = {"tim_kiem_san_pham": tim_kiem_san_pham, "tinh_toan": tinh_toan}
TOOL_SCHEMAS = [
    {"name": "tim_kiem_san_pham",
     "description": "Tìm sản phẩm trong kho theo từ khóa. Dùng khi người dùng hỏi có bán gì, giá bao nhiêu.",
     "input_schema": {"type": "object",
        "properties": {"tu_khoa": {"type": "string"},
                       "gia_toi_da": {"type": "integer", "description": "VNĐ"}},
        "required": ["tu_khoa"]}},
    {"name": "tinh_toan",
     "description": "Tính biểu thức số học, ví dụ '450000*2*0.9'.",
     "input_schema": {"type": "object",
        "properties": {"bieu_thuc": {"type": "string"}}, "required": ["bieu_thuc"]}},
]

# 2. Vòng lặp agent
def chay_agent(yeu_cau: str, so_buoc_toi_da: int = 10) -> str:
    messages = [{"role": "user", "content": yeu_cau}]
    for buoc in range(so_buoc_toi_da):
        resp = client.messages.create(
            model=MODEL, max_tokens=1000, tools=TOOL_SCHEMAS, messages=messages,
            system="Bạn là trợ lý bán hàng. Dùng tool để tra cứu, không tự bịa giá.")
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason != "tool_use":           # mô hình đã xong
            return "".join(b.text for b in resp.content if b.type == "text")

        ket_qua = []
        for block in resp.content:
            if block.type == "tool_use":
                print(f"[bước {buoc}] gọi {block.name}({block.input})")
                try:
                    out = TOOLS[block.name](**block.input)
                    ket_qua.append({"type": "tool_result", "tool_use_id": block.id,
                                    "content": json.dumps(out, ensure_ascii=False)})
                except Exception as e:                # báo lỗi cho mô hình tự sửa
                    ket_qua.append({"type": "tool_result", "tool_use_id": block.id,
                                    "content": f"Lỗi: {e}", "is_error": True})
        messages.append({"role": "user", "content": ket_qua})
    return "Dừng vì vượt quá số bước cho phép."

print(chay_agent("Mua 2 tai nghe dưới 500k, giảm 10% thì hết bao nhiêu?"))

Điểm cần hiểu: giới hạn số bước để không lặp vô hạn; lỗi của tool được trả về cho mô hình thay vì làm sập chương trình; mọi bước đều được in ra để theo dõi.

Thiết kế tool tốt

  • Tên và mô tả là prompt: nói rõ tool làm gì, khi nào dùng, khi nào không dùng, đơn vị của tham số.

  • Ít tool nhưng mạnh: gộp các thao tác hay đi cùng nhau; 5–15 tool rõ ràng tốt hơn 50 tool chồng chéo.

  • Kết quả gọn và có ích: trả về đúng trường cần thiết, cắt bớt khi quá dài, có phân trang.

  • Thông báo lỗi hướng dẫn cách sửa: "Thiếu tham số thanh_pho, hãy hỏi người dùng" thay vì "KeyError".

  • Phân quyền: tool chỉ đọc chạy tự do; tool ghi/xóa/thanh toán/gửi email cần người dùng xác nhận.

MCP (Model Context Protocol)

MCP là chuẩn mở để kết nối ứng dụng AI với tool và dữ liệu bên ngoài: viết tool một lần dưới dạng MCP server, mọi ứng dụng hỗ trợ MCP (Claude, IDE, framework agent) đều dùng được.

  • Server cung cấp: tools (hành động), resources (dữ liệu đọc), prompts (mẫu prompt).

  • Client nằm trong ứng dụng AI, kết nối tới server qua stdio (chạy local) hoặc HTTP (chạy từ xa).

python
# pip install "mcp[cli]"
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("ghi-chu")

@mcp.tool()
def them_ghi_chu(noi_dung: str) -> str:
    """Thêm một ghi chú mới."""
    with sqlite3.connect("notes.db") as c:
        c.execute("CREATE TABLE IF NOT EXISTS n (id INTEGER PRIMARY KEY, t TEXT)")
        c.execute("INSERT INTO n (t) VALUES (?)", (noi_dung,))
    return "Đã lưu"

@mcp.tool()
def tim_ghi_chu(tu_khoa: str) -> list[str]:
    """Tìm ghi chú chứa từ khóa."""
    with sqlite3.connect("notes.db") as c:
        return [r[0] for r in c.execute("SELECT t FROM n WHERE t LIKE ?", (f"%{tu_khoa}%",))]

if __name__ == "__main__":
    mcp.run()          # thử bằng: mcp dev server.py

    loai: str
    tra_loi: str

Multi-agent

Chỉ dùng khi một agent đơn thật sự quá tải: công việc chia được thành phần độc lập chạy song song, hoặc mỗi phần cần ngữ cảnh riêng quá lớn. Mô hình phổ biến nhất là agent điều phối + các agent con: điều phối lập kế hoạch, giao việc kèm hướng dẫn rõ, nhận kết quả gọn và tổng hợp. Multi-agent tốn nhiều token hơn hẳn và khó debug hơn.

Dự án

  1. Agent nghiên cứu: tool tìm web + đọc trang + ghi file; nhận một chủ đề, tự tìm 5–10 nguồn, viết báo cáo Markdown có trích dẫn.

  2. Agent chăm sóc khách hàng: tra đơn hàng trong SQLite, tra chính sách bằng RAG (chặng 5.3), tạo yêu cầu hoàn tiền nhưng phải chờ người duyệt; viết bằng LangGraph.

  3. MCP server của riêng bạn: ví dụ cho Google Sheets, Notion hoặc API công ty; kết nối vào Claude Desktop hoặc IDE; công khai trên GitHub.

Lỗi hay gặp
Dùng agent cho việc một lệnh gọi là đủ; mô tả tool mơ hồ khiến mô hình gọi sai tool; không giới hạn số bước và ngân sách token; nhồi toàn bộ kết quả tool rất dài vào ngữ cảnh; cho agent quyền xóa/gửi/thanh toán mà không có bước xác nhận.

Tracing và giám sát

Tracing ghi lại từng bước của agent: prompt gửi đi, câu trả lời, tool đã gọi, tham số, thời gian, số token. Khi agent "làm gì đó kỳ lạ", trace là cách duy nhất để biết vì sao.

  • Công cụ: Langfuse (mã nguồn mở, tự cài được), LangSmith, Arize Phoenix, hoặc chuẩn OpenTelemetry.

  • Chỉ số cần theo dõi: tỷ lệ hoàn thành, số bước trung bình, độ trễ (p50, p95), chi phí mỗi tác vụ, tỷ lệ lỗi tool, phản hồi 👍/👎 của người dùng.

  • Tự làm tối thiểu: ghi log JSON mỗi lệnh gọi LLM và tool vào file hoặc database, kèm trace_id cho cả phiên.

Vận hành ổn định

  • Tác vụ chạy lâu: đưa vào hàng đợi (Celery, RQ, hoặc ARQ với Redis), trả task_id ngay, client hỏi lại trạng thái hoặc nhận webhook.

  • Cache: lưu kết quả của câu hỏi trùng lặp; bật prompt caching của nhà cung cấp cho system prompt dài.

  • Rate limit: giới hạn số yêu cầu và ngân sách token mỗi người dùng mỗi ngày.

  • Fallback: khi model chính lỗi hoặc quá tải, chuyển sang model dự phòng; có timeout cho mọi lệnh gọi.

  • Checkpoint: lưu trạng thái agent sau mỗi bước để chạy tiếp khi server khởi động lại.

  • CI/CD: GitHub Actions chạy pytest + evals mỗi lần push; điểm evals tụt thì chặn deploy.

Dự án tốt nghiệp

Chọn một vấn đề thật của bạn hoặc của một doanh nghiệp quen biết, rồi xây agent giải quyết nó từ đầu đến cuối. Gợi ý:

  • Agent kế toán: đọc hóa đơn PDF/ảnh trong email, trích xuất, đối chiếu, ghi vào Google Sheets, hỏi lại khi không chắc.

  • Agent tuyển dụng: đọc CV, chấm theo mô tả công việc, soạn email mời phỏng vấn chờ người duyệt.

  • Agent phân tích dữ liệu: nhận câu hỏi tiếng Việt, viết SQL, chạy trên database, vẽ biểu đồ, giải thích kết quả.
